# 찬양대 음향 체크 기록

주간 찬양대 음향 분석을 확정 기록으로 보관하고 팀 메모를 나누는 웹사이트. 로그인 없이 접속하는 메인 화면과 작성 화면, 미연결 AI 인터페이스 및 예외처리가 구현되어 있습니다. 수동 기록의 로컬 영구 저장, 날짜 트리, 영상 및 댓글이 구현되었습니다. 실제 AI와 PDF는 후속 구현 대상입니다.

## 로컬 실행

프로젝트 폴더에서 `python server.py` 실행 후 http://127.0.0.1:4174 에 접속합니다. Node.js가 있다면 `npm test`로 분석 인터페이스의 예외처리 테스트를 실행합니다. 외부 패키지 설치는 필요하지 않습니다.

작성 중 입력은 페이지 메모리에 유지됩니다. AI 미연결 오류 후 수동 폼을 작성하여 확정하면 영상과 기록을 data/에 저장합니다. 확정된 기록과 댓글은 새로고침 후에도 유지됩니다. 서버의 고유 요청 키로 중복 저장을 막고 DB에서 본문 수정을 차단합니다. 검증 결과와 롤백 방법은 REVIEW.md를 참고하세요.

## 화면 흐름

최신 화면: [AI 분석결과]와 편집 가능한 개선할 점을 표시합니다. 유지할 장점과 다음 주 실행 계획은 제거했습니다. 새 기록에는 찬양대 인원 및 마이크 번호가 필수이며, 담당자는 색상 배지로 구분합니다. 댓글은 수정 및 삭제(숨김)가 가능합니다. 원본 분석결과는 유지하고 개선점 편집은 별도 저장합니다. 자세한 최신 검증 결과는 REVIEW.md를 참고하세요.

- 헤더 제목: 찬양대 음향 체크 기록. 헤더에는 업로드/분석 버튼을 두지 않습니다.
- 왼쪽: 연도 > 월 > 날짜 트리. 목록 아래 은은한 `+` 버튼(접근 가능한 이름: 새 기록 추가). 키보드 포커스와 충분한 명암을 제공합니다.
- `+` 클릭: 별도 작성 페이지로 이동. 날짜, 온라인 송출담당자, MP4 업로드 입력란과 아래 `생성 및 분석` 버튼.
- 날짜 클릭: 오른쪽에 확정 기록, 영상, 핵심 피드백, 장점, 개선 우선순위, 시간대별 근거, 측정값, 다음 주 실천 제안 및 PDF 보고서 다운로드.
- 기록 아래: 이름과 메모를 입력하는 별도 댓글 공간. 댓글은 작성 시각과 함께 표시하고 분석 원문과 분리합니다.

## 기록 확정 및 중복 요청 방지

1. 작성 중에는 입력값을 수정할 수 있습니다.
2. 서버가 파일 형식·크기·오디오 존재와 필수 입력값을 검증합니다.
3. 생성 요청에 고유 요청 키를 부여합니다. 서버의 유일성 제약과 트랜잭션으로 중복 클릭·새로고침이 새 분석을 만들지 않게 합니다.
4. 상태는 대기 → 분석 중 → 완료 또는 실패. 제출 직후 버튼을 잠그고 기존 작업 상태를 표시합니다.
5. 분석 단계별 결과를 저장합니다. 실패 시 동일 작업을 재개하며 성공한 단계는 재사용합니다. 외부 AI 응답이 불명확한 경우 무조건 재호출하지 않고 확인 상태로 둡니다. 외부 제공자가 멱등성을 지원하지 않으면 정확히 한 번 호출을 절대 보장할 수 없습니다.
6. 분석 성공 시 날짜·담당자·영상 식별자·측정값·분석 결과·분석 버전·확정 시각을 하나의 트랜잭션으로 확정합니다.
7. 확정된 본문은 UI뿐 아니라 서버 및 DB 권한/제약에서도 변경을 막습니다. 정정은 별도 메모로 남깁니다. 이 commit은 데이터 확정이며 Git 커밋과 별개입니다.
8. 댓글은 별도 테이블에 추가합니다. 댓글 작성은 AI 호출을 발생시키지 않습니다.
9. PDF는 확정 분석 본문으로 생성·캐시합니다. 댓글은 변하는 소통 기록이므로 기본 PDF에서 제외합니다.

파일 해시와 날짜를 이용해 동일 영상의 중복 등록을 안내하고, 사용자별 요청 제한과 서버 작업 잠금도 적용할 계획입니다.

## 분석 원칙

음량·피크·주파수·좌우 균형의 수치 측정과 AI 해석을 구분합니다. 직접 오디오를 분석했는지 수치만 해석했는지 표시합니다. 근거 없는 성부·악기 식별이나 점수를 만들지 않습니다. 장점, 개선 우선순위, 시간대별 근거, 다음 주 실행 및 검증 방법을 중심으로 작성합니다.

## GitHub 동기화와 복원

저장소: https://github.com/cro-cop-kyc/choir-sound-log

새 PC 또는 폴더 삭제 후:

```sh
git clone https://github.com/cro-cop-kyc/choir-sound-log.git
cd choir-sound-log
```

작업 전 `git pull --ff-only`, 작업 후 변경 파일을 확인하여 `git add`, `git commit`, `git push`합니다. GitHub에 push하지 않은 작업은 복구되지 않습니다. 의존성 잠금 파일, 환경설정 예제, 실행 및 배포 지침은 구현 시 함께 관리합니다.

영상·DB·PDF는 별도 영구 저장소와 백업이 필요합니다. GitHub는 코드의 복구 경로이며 운영 데이터의 백업을 대신하지 않습니다. API 키는 서버 환경변수로 관리합니다.
